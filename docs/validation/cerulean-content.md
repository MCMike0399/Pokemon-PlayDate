# Cerulean source content candidate

Prepared on `wip/cerulean-map-content` after merging exact foundation candidate
`9f3e37ba3c62daf40c229e802c61cec702c97cb3`. This is content preparation, not
campaign or native acceptance. Root owns Simulator, integration and the ledger.

The shared decoder imports 18 English Blue maps at pokered revision
`af519899719f0754965776faac0e836a3b906e6d`: Route22, Route3, MtMoon1F,
MtMoonB1F, MtMoonB2F, Route4, MtMoonPokecenter, CeruleanCity, CeruleanGym,
CeruleanPokecenter, CeruleanMart, BikeShop, CeruleanTrashedHouse, Route24,
Route25, BillsHouse, Museum1F and Museum2F. The additional Route4 Center is a
normal source ingress needed by the route. Museum floors use actual source
names, not invented PewterMuseum names.

## Data and pipeline

`Source/data/sourceSlice` contains decoded geometry, collision, source block
references, warps, header connections, Blue grass/water tables, objects, signs,
text recipes, script source/indexes and direct trainer rosters. Raw script text
is an audit input, never an interpreter or an executable campaign substitute.
Every consumed source file is pinned in `tools/references/cerulean-content.json`.
The provenance record hashes all generated artifacts and the generator itself.

Each new map carries its exact music symbol and symbolic audio bank expression
from its slot in `data/maps/songs.asm`, including the original source line.
For example, Route3/4 use MUSIC_ROUTES3, while Route24/25 use MUSIC_ROUTES2.
BANK(Music_...) stays symbolic; this batch does not guess linked ROM bank numbers
or install audio hooks. Existing map metadata is unchanged.

`ceruleanSourceMaps.json` is the complete proposed 30-map manifest, and
`ceruleanMapCache` is generated by the existing shared cache generator. There is
no new geometry provider, regional constructor, renderer or cache implementation.
`sourceSlice/manifest-entries.json` contains just the 18 additions.

The active `sourceMaps.json` and `sourceMapCache` remain byte-identical to the
foundation. Adding these maps directly to the active inventory makes previously
missing exits resolve in the current foundation. Its runtime projection does
not consistently enforce manifest blockers. A separate candidate manifest and
cache therefore preserve the current campaign until root integrates and accepts
5.2. The proposed manifest also explicitly retains all previous surface blockers
and adds the previously unavailable Pewter east/Viridian west boundary gates.
Those gates need the shared runtime fixes described in the integration note.

## Ordinary content and reserved scenes

`CeruleanContent` registers 79 ordinary object descriptors, 41 direct trainer
definitions and the source actor/text resolvers through SourceEvents and
SourceActors. Descriptors cover ordinary trainer battles, visible item pickups,
static and conditional dialogue, Center healing/checkpoints, the Mart and the
Old Amber gift with capacity retry. The gift's museum display visibility follows
EVENT_GOT_OLD_AMBER. The original Mart stock already belongs to ItemData.

Sixteen sign programs are exposed separately because foundation registration
currently validates only object IDs. `installSigns()` is ready after root widens
that shared validation. They do not use a separate event dispatcher.

All object and sign rows are accounted for as ordinary descriptors or explicit
gaps in `scripts.json`. Bill's three actors, Super Nerd/fossils, and Misty have
no ordinary descriptor registration; the story worker owns those planners.
Their exact source text and direct rosters are available here. Full Rival1 and
Rival2 class rosters are also retained without choosing a starter branch.

Remaining bespoke work includes the two rival approaches/departures and their
starter selection, Nugget Bridge prize/Rocket sequence, robbery Rocket/TM28 and
guard visibility, bicycle voucher exchange, Magikarp purchase, museum admission,
conditional Cerulean girl/Slowbro interactions, Bill/fossil/Misty scene visibility
and source hidden-event interactions. Link receptionists remain explicit gaps.
Hidden event positions/function names and source hide/show declarations are
retained; they are not claimed playable. The older Viridian tutorial and Pewter
escort remain root's earlier backlog.

## Art family provenance

All 28 actor strips are read from immutable pokered PNGs through the existing
`generate_viridian_slice.sprite_data` converter. All four source shades and each
16×16 frame are preserved. Runtime keys are private `cerulean_sprite_*` keys;
accepted RED/BLUE/Oak, other existing NPC outputs and protected art are untouched.
Frames use the existing SpriteFactory flood-fill alpha mask and explicit phase
`{0, 0}`. Walking uses the established eight-tick phase sequence and mirrored
left/right source frames. Art installs only for objects on the loaded map.

Terrain uses the existing `generate_kanto_maps.decode_map` conversion, canonical
stable tile IDs and the shared explicit-phase renderer. Host checks independently
index original block bytes and use Pillow to compare every decoded grid against
the source tilesheet. Host checks also compare every sprite frame pixel against
its pinned PNG. Native-size and in-motion review remains root-owned; this batch
makes no visual acceptance claim.

## Reproduction

```sh
source ~/Developer/Pokemon-PlayDate-env/env.sh
python tools/generate_cerulean_content.py --reference "$POKERED_REFERENCE_DIR" --check
python tools/generate_source_map_cache.py --manifest Source/data/ceruleanSourceMaps.json --output Source/data/ceruleanMapCache --check
python -m unittest tools.tests.test_cerulean_content -v
```

Generation requires an explicit reference directory, verifies consumed bytes,
and writes only a fresh explicit output directory. `--check` compares checked-in
content, proposed manifest and proposed shared cache without writing. Host checks
fail on missing inputs, altered pins, output drift, missing/extra files and text
or roster inconsistencies. They execute neither Lua nor an SDK substitute.

`dev/ceruleanContentContracts.lua` adds root-run real SDK contracts for all 18
shared source projections, every ordinary plan, full/repeated rewards, text
rendering, production species resolution, detached records and native actor
image/mask construction. It is intentionally not added to dev_imports.lua by
this worker. Registration and activation instructions are in
[the root integration note](../plans/cerulean-content-integration.md).

Worker verification on 2026-10-26: generator `--check` and shared candidate-cache
`--check` passed. The relevant host suites passed 88 tests with zero skips,
including the 13 new content checks, source maps/events/text, original map and
sprite generators, capture-policy staging and production build checks. Real
SDK3.1.2 production and harness compilation passed. Durable build evidence is
`~/Developer/Pokemon-PlayDate-env/evidence/cerulean-content-build-20261026-01`
and `cerulean-content-production-20261026-01`. The compiled harness contains the
