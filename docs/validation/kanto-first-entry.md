# Kanto first-use preparation

Implementation candidate only. Root owns every runtime, device and acceptance
check. The measured 1,172 ms installer is the target, not a measured saving.
This packet has no dependency on the isolated title split or its new methods.

`CeruleanStory.install` and `CeruleanRoutes.install` can publish generated
membership through SourceEvents' existing region declaration mechanism. This
makes event, trainer, item and source-flag membership available before
TrainerEvents captures its immutable lookup. Descriptor bodies and rival teams
resolve individually through the existing eight-record cache, including direct
`descriptor`, trainer lookup, plan, pages and dispatch callers. No new registry,
session owner, movement owner, per-map cache or game closure is introduced.

The qualified installer does not read story event/dialogue/scene/trainer files,
construct script-position copies, decode the rival-class catalogue or construct
six rival variants at boot. The exact SDK-transformed descriptors and teams are
content-addressed chunks. Shared trainer prerequisites and namespace conflicts
are still checked before atomic event/trainer publication. Actor metadata and
reconciliation stay with the existing owners.

World hook and bespoke callback registration remains at boot. This is partial
activation: first use loads the required descriptor/roster and scene fields;
there is no claim that every region service or import is lazy. Story dialogue,
events, scenes and trainers load independently, and unrelated map callbacks do
not demand story scenes. These fixed cluster fields can remain resident after
use; the descriptor cache stays bounded. Public getters retain defensive copies.

## Disabled pending exact SDK evidence

There is deliberately no `tools/integration/kanto-first-entry/qualified/` in this
commit. Without a qualified export, production takes the deep installer path.
The field split alone is not the proposed performance result. Harness/dev,
custom source inputs and SourceMaps record fixtures retain deep registration.
A fixture cannot borrow the qualified map-padding identity. Qualified reads use
PDX-only access. No device/memory gate changes.

Root commands, from the final integrated checkout after its active device
sequence (use a new output directory):

```sh
source ~/Developer/Pokemon-PlayDate-env/env.sh
python3 tools/integration/kanto-first-entry/export.py --output "$HOME/Developer/Pokemon-PlayDate-env/evidence/kanto-first-entry-sdk-UNIQUE" --execute
python3 tools/integration/kanto-first-entry/export.py --output "$HOME/Developer/Pokemon-PlayDate-env/evidence/kanto-first-entry-sdk-UNIQUE" --collect
```

The first command uses the existing identified harness, locks and ownership;
the worker has not executed it. Its private hook wraps the original deep
installers and exports their actual SDK descriptors, newly registered teams and
shared trainer prerequisites. The harness archives the export in `runtime-data`
and exits normally. Collection requires a successful matching harness outcome
and hashes the actual copied Source dependencies/cache, build and outcome.
It creates the two optional qualification files locally; review and retain those
files separately as Root-owned evidence. Never reuse or relabel an older
producer. There are no new imports or contract registrations to add to main.

The generator validates those dependencies in both the checkout and copied
runtime Source, the copied feature imports, pinned content inputs and every
copied cache byte before producing declarations. Existing production staging
sets trust only after successful qualification and removes stale copied optional
declarations. Existing immutable conflict/transform checks run in the SDK export
and remain in the deep fallback. No Python translation of Lua is used.
Changes to SourceMaps' manifest (including a different 108/149 map build), owner
code or cache require a fresh compatible export. Do not combine old producer
hashes with new source. Export/collection is a prerequisite, not acceptance.

Root still needs deep versus qualified first-use equivalence, direct descriptor
and trainer lookups before any journey, membership/source-flag/save validation,
namespace rejection and fixture-scope restoration, exact positions/rosters/text,
actor reconciliation and callbacks/RNG/copy isolation. Then exact 16 MiB safety,
installer attribution and one hardware comparison must establish at least a
10% installer-phase improvement without weakening existing memory/latency gates.
The worker claims no runtime, timing, memory, visual or acceptance result.
